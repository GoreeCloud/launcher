## Planned next capabilities

### Universal Search

- Complete representative-device visual, large-text, touch-target, accessibility, and provider-state acceptance for the implemented compact grouped Search Sources manager; continue reducing presentation density only where privacy/permission/provider truth remains equally clear.
- Adopt provider-control state into a separately versioned portable backup/recovery migration only after compatibility, restore, explicit-empty semantics, and rollback behavior are defined and tested.
- Keep truthful explicit online handoffs for providers that do not yet have a reviewed inline adapter, but present them inside the unified Universal Search result surface rather than as a separate no-results provider strip. A handoff-only source must never authorize live typed-query fan-out merely because its toggle is enabled.
- Continue issue #252 provider work only with provider-specific authority. For the implemented Development Google Drive adapter, complete representative-device Google Identity consent, Android OAuth-client/package-signing configuration, Drive API enablement, shared-drive/result-opening behavior, token-expiry/reconnect, revocation, cancellation, and profile/account acceptance; do not regress to Android SAF/Drive-folder selection as an account surrogate. Brave Autosuggest still requires the official service through a governed server-side confidential credential/proxy or user-owned credential path with no embedded long-lived APK secret. Gmail requires approved OAuth message search without Launcher retention of message content; Dropbox requires least-privilege authenticated search; and other providers require equivalent trust, revocation, retention, profile/account, cancellation, stale-query suppression, and failure contracts.
- Add external provider discovery/registration only after trust boundaries, compatibility/versioning, revocation behavior, package/profile isolation, and user-facing provider information are accepted.
- Add richer local sources, settings/actions, shortcuts, commands, and permission-aware result categories before optional GoreeCloud Search / GoreeCloud Index integrations.
- Define privacy-preserving recents/history/context semantics before storing or using query/activity history; core Search must remain useful with those features disabled.
- Evaluate partial/streaming result presentation only if measured evidence shows that it improves interaction quality.

### Profile and Android-system acceptance
